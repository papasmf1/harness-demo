# 행사 후 회고 작성 매뉴얼

## 목적

행사가 끝난 뒤 경험을 구조화된 문서로 남겨서, 다음 번 행사를 더 잘 준비할 수 있게 합니다.

## 절차

1. `event/plan.md`를 읽어 원래 계획을 파악한다.
2. 실행 메모와 원래 계획을 비교한다.
3. Keep → Problem → Try 순서로 작성한다.
4. 다음 행사를 위한 구체적인 개선 제안을 포함한다.

## 3단 구조

| 항목 | 질문 | 톤 |
|---|---|---|
| Keep (잘 된 것) | 계획대로 잘 작동한 것은 무엇인가? | 긍정적, 구체적 |
| Problem (힘들었던 것) | 예상보다 어려웠거나 계획과 달랐던 것은? | 사실 중심, 비판 없이 |
| Try (다음에 바꿀 것) | 다음 번에 바꾸면 더 나아질 것은? | 실행 가능한 제안 |

## 산출물 형식

```md
# [행사 이름] 회고록

- 행사 날짜: 
- 작성일: 
- 참가 인원: 

---

## Keep — 잘 된 것
- 

## Problem — 힘들었던 것
- 

## Try — 다음에 바꿀 것
- 

---

## 다음 행사를 위한 메모

> 다음 번에 가장 먼저 바꿀 한 가지:

> 계속 유지하고 싶은 한 가지:

> 추가로 준비하면 좋을 것:
```

## 품질 기준

- Keep·Problem·Try 세 항목은 모두 작성합니다.
- 각 항목에 최소 2-3개 내용을 포함합니다.
- "다음에 바꿀 것"은 실행 가능한 수준으로 구체적으로 씁니다. ("더 잘하자"가 아니라 "음료를 1인당 2개로 늘린다")
- 실행 메모가 없으면 오케스트레이터에게 메모를 먼저 요청합니다.

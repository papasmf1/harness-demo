# 취미 진도 점검 매뉴얼

## 목적

한 달에 한 번, 실제로 얼마나 진행됐는지 확인하고 다음 달 계획을 현실에 맞게 조정합니다. 잘한 점을 확인하고 막힌 지점을 찾는 게 목적입니다. 평가가 아닙니다.

## 절차

1. `hobby/plan.md`를 읽어 이번 달 마일스톤을 파악한다.
2. 사용자 실행 메모와 마일스톤을 비교한다.
3. Keep → Problem → Try 순서로 보고서를 작성한다.
4. 다음 달 루틴 조정 제안을 포함한다.
5. `hobby/progress.md`에 날짜 헤더와 함께 추가한다 (기존 내용 덮어쓰지 않음).

## 3단 구조

| 항목 | 질문 | 톤 |
|---|---|---|
| Keep (잘 된 것) | 꾸준히 한 것, 예상보다 잘 된 것은? | 구체적, 긍정적 |
| Problem (막힌 것) | 계획대로 안 된 것, 어려웠던 것은? | 사실 중심, 비판 없이 |
| Try (다음 달 바꿀 것) | 다음 달에 하나 바꾼다면? | 실행 가능한 제안 1-2개 |

## 산출물 형식

```md
---

## [YYYY년 M월] 진도 점검

**작성일:** YYYY-MM-DD
**이번 달 목표:** (plan.md에서 발췌)
**실제 연습 횟수:** 회 / 계획 회

### Keep — 잘 된 것
- 

### Problem — 막힌 것
- 

### Try — 다음 달 바꿀 것
- 

### 다음 달 마일스톤 조정
- 원래: 
- 조정: (필요 시)
```

## 품질 기준

- Keep·Problem·Try 세 항목 모두 작성합니다.
- "Try"는 실행 가능한 수준으로 구체적으로 씁니다. ("더 열심히"가 아니라 "매주 화요일 30분 추가")
- 기존 progress.md 내용을 덮어쓰지 않고 맨 아래에 추가합니다.
- 실행 메모 없이 보고서를 지어내지 않습니다.
